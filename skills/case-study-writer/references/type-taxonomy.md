# Case-study type taxonomy

Nine types plus five variants, each dissected off a real live page (or labelled secondhand where the page could not be fetched). Every length target is justified by what that format needs, not a house default. Section spines are the actual heading orders observed, compressed to a reusable shape.

## 1. How to use this file

Pick ONE type in Step 2. Use its section order as the draft spine and its length target as the budget. The senior-signal set (role, constraints, first attempt, failure, trade-offs, one hard number) is required in every type; the type only changes the shape and emphasis, not that requirement.

<a name="the-9-types"></a>
## 2. The 9 types

### 1. Story / reframing-led  (~4,000 words)
- **Recommend when:** a senior IC project with a narrative-worthy decision and a clear frame-shift (the problem-as-seen was wrong, you renamed it, solutions follow the new frame).
- **Real exemplar:** Simon Pan, "Perfecting the Pickup" (Uber).
- **Spine:** scene+tension hook → the challenge (with constraint/timeline) → role → early insights → the reframe ("how might we…") → solutions each mapped to the new frame (from X to Y) → launch → impact (honest, modest numbers).
- **Length justification:** long because the value IS the frame-shift arc plus several solution sections tied to it; compressing it kills the reasoning that signals seniority.
- **Ending:** impact with a stated honest failure ("I killed that idea after the third round").

### 2. Results / impact-first  (~2,800 words)
- **Recommend when:** real post-launch metrics exist and are yours to show.
- **Real exemplar:** Elise Fu, "Komeeda".
- **Spine:** title + one-line mandate → role/team/duration → headline metrics block up top → background → the narrative told backwards from the numbers, per surface → results → conclusion & learning.
- **Length justification:** needs room to walk the before/after per surface that produced the headline numbers; shorter and the metrics look unearned.
- **Ending:** results, then a short learning beat. Weak type if you have no measured outcome.

### 3. Agency / client  (~700 words)
- **Recommend when:** an agency/client engagement where the deliverable is a relationship, an approach, or press, not a metric.
- **Real exemplar:** IDEO × Boom Supersonic.
- **Spine:** title + client one-line promise → headline stat (deposits/orders) → narrative (context → partnership → approach → feedback moment) → client quote → key facts → press → related work + CTA.
- **Length justification:** deliberately short; brevity signals confidence and the client is the hero, so a long process narrative would be off-key.
- **Ending:** press mentions + contact CTA.

### 4. Company-blog team narrative  (~2,400 words)
- **Recommend when:** the project is a team story and the audience is the employer/recruiting brand.
- **Real exemplar:** Figma, "Code, craft, and the making of nested folders".
- **Spine:** announce + why it was hard → the process change → three first-person perspectives (eng / design / PM) → team rituals + launch → bios. Often NO heading hierarchy, one bylined essay.
- **Length justification:** room for multiple first-person voices; the "result" is the way of working, which needs narrative space.
- **Ending:** the team's way of working, not a metric. Note: this is an employer-brand piece, not a personal hiring document.

### 5. Passion-project / personal-narrative  (~1,700 words)
- **Recommend when:** Kriss's own side project; proves initiative and taste, good when shipped client work is thin.
- **Real exemplar:** Steph Parrott, "Plantd".
- **Spine:** personal-motivation hook → overview → goals → role/process → app overview → research → competitors → interviews → a key feature → from design to development → what's next.
- **Length justification:** medium; enough for the motivation + build story without a full metrics apparatus a side project rarely has.
- **Ending:** "What's next" (beta learnings), a non-resolving close is acceptable here.

### 6. Double-diamond / process-phase  (~1,500 to 2,500 words) — JUNIOR TIER
- **Recommend when:** coursework or a junior portfolio where the process IS the product being demonstrated.
- **Exemplar:** Angelica Araujo, Paperchase (secondhand, structure only).
- **Spine:** Discover → Define → Ideate/Develop → Deliver.
- **CAUTION:** this is the process-phase spine the craft rules warn against for senior work. Only choose it if Kriss is explicitly targeting junior/coursework framing; otherwise steer to reframing-led or decision-led.
- **Length justification:** range, secondhand (pages not fetched); do not over-pad.

### 7. Mock-project / teardown redesign  (~1,200 to 2,000 words) — JUNIOR TIER
- **Recommend when:** no shipped work; a self-initiated redesign or concept.
- **Exemplars:** Morgan Bathe Spotify concept, Leslie "Meal Planner" (secondhand).
- **Spine:** problem → market/competitive stats → interviews → POV / how-might-we → flows/wireframes → prototype tests → reflection.
- **CAUTION:** concept redesigns rank below shipped work to a screener; use only when there is no real project. Range is secondhand.

### 8. Per-feature / modular container  (~2,000 to 3,000 words)
- **Recommend when:** one long engagement with several shipped pieces; the case study is a container of mini-stories.
- **Real exemplar:** Steph Parrott / Square (four shipped sub-projects, one rhythm each); Adam Fard EdTech (secondhand).
- **Spine:** overview → role & process → goals → featured projects list → per-feature blocks, each with the same internal before/after + evidence rhythm → more work.
- **Length justification:** scales with the number of sub-projects; each mini-story is short, the total adds up.
- **Ending:** route to more work.

### 9. STAR (Situation, Task, Action, Result)  (150 to 300 words)
- **Recommend when:** an interview answer or a resume bullet, not a portfolio page.
- **Anchor:** Levashina et al. 2014 (structured-interview meta-analysis).
- **Spine:** Situation/Task (context + goal) → Action (what you did) → Result (metric/outcome).
- **Length justification:** the compressed spoken/bullet form; anything longer stops being STAR.

<a name="the-5-variants"></a>
## 3. The 5 variants (pick if closer than the parent type)

- **Problem-first** (Latiesha Caston, ~1,200 to 1,800): opens cold on the problem, no scene-setting; ends on Challenges (honesty), not results. Good senior default when there is a sharp problem and modest metrics.
- **Decision-led** (Karolis Kosas, ~1,500 to 2,500): sections named after decisions, sized by how much each mattered; research appears as a single quantified insight where it changed a decision. The cleanest senior spine.
- **Multi-project container** (see type 8).
- **Artifact-led** (Karri Saarinen DLS, 300 to 450): headings are the artifact's anatomy (Components / iOS vs Android / Adoption), role in line one, almost no numbers, non-resolving ending. See the caution below.
- **Feature-description** (Gavin Nelson, short): describe the shipped feature and the craft, minimal narrative.

<a name="craft-artifact-tier"></a>
## 4. The craft-artifact tier caution

Designers at Vercel/Linear/Figma tier often publish named usable artifacts, ongoing "craft" practice, and opinion essays INSTEAD of case studies (300 to 450 words, role in line one, no process spine, numbers nearly absent, non-resolving endings). This proves **standing already held**, not **competence to a screener**. The moves that transfer for free: role in the first line, no process-phase spine, headings named after the thing not the journey, brevity. Do NOT copy the absent numbers and non-resolving endings when writing for a screener who needs exactly those. Only lean fully artifact-led when Kriss's name already carries public standing for that work.

<a name="length-summary"></a>
## 5. Length-justification summary

| Type | Target | Why this length |
|---|---|---|
| Reframing-led | ~4,000 | frame-shift arc + multiple mapped solution sections |
| Results-first | ~2,800 | before/after per surface behind the metrics |
| Agency/client | ~700 | brevity signals confidence; client is hero |
| Company-blog | ~2,400 | multiple first-person voices |
| Passion-project | ~1,700 | motivation + build, light on metrics |
| Double-diamond | 1,500 to 2,500 | junior tier; do not pad (secondhand) |
| Mock-project | 1,200 to 2,000 | junior tier (secondhand) |
| Per-feature | 2,000 to 3,000 | scales with sub-project count |
| STAR | 150 to 300 | compressed interview/bullet form |
| Problem-first | 1,200 to 1,800 | sharp problem + modest metrics |
| Decision-led | 1,500 to 2,500 | one section per decision |
| Artifact-led | 300 to 450 | anatomy of the artifact; presumes standing |
